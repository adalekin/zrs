# Proposal

## Why

Модератор может утвердить запрос окончательно, и тогда финансовый директор его не видит: проверка расхода по деньгам остаётся необязательной. Второй уровень согласования нужен каждому запросу, а не по выбору модератора.

## What Changes

- «Утвердить» модератора переводит запрос в статус «Отмодерировано»: дальше решает финансовый директор.
- Отдельного действия «Передать финансовому директору» больше нет: утверждение модератора и есть передача.
- Статус «Одобрено» ставит только финансовый директор; возврат и отказ у обеих ролей не меняются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `expense-requests`: второй уровень согласования обязателен для каждого запроса.

## Impact

- Сервер: таблица переходов, набор решений в Telegram, ответ бота о выполненном действии выбирается по итоговому статусу. Схема базы не меняется; кнопки, предложенные до обновления (действие `escalate`), отвечают «Кнопка больше не действует».
- API: действие `escalate` уходит из перечисления действий.
- Веб-интерфейс: кнопки «Передать финансовому директору» больше нет; подпись «Утвердить» у модератора остаётся.
- Спецификация незаархивированного изменения `decide-in-telegram` правится на месте: у модератора три кнопки.
- Новых зависимостей нет.
