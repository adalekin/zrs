# Proposal

## Why

Сообщение бота говорит согласующему, что запрос ждёт его решения, но принять решение можно, только открыв сервис и войдя в него. Согласующий, который прочёл сообщение с телефона, откладывает решение до компьютера.

## What Changes

- Сообщение о запросе, который ждёт решения модератора или финансового директора, несёт кнопки доступных ему решений.
- Утверждение, одобрение и передача финансовому директору выполняются нажатием кнопки.
- Возврат и отказ бот выполняет после того, как человек напишет причину или откажется её писать.
- Решение принимается от имени человека, к которому привязан чат, по его ролям на момент последнего входа в сервис.
- Установка явно включает решения из Telegram.

## Capabilities

### New Capabilities

- `telegram-decisions`: решения по запросам из сообщений бота Telegram.

### Modified Capabilities

- `installation-settings`: установка включает решения из Telegram.

## Impact

- Сервер: кнопки в сообщениях об очереди, обработка нажатий и текстовых ответов в задаче приёма обновлений, действие над запросом от имени привязанного человека. Схема базы получает одну миграцию.
- API не меняется; страница уведомлений показывает, включены ли решения из Telegram.
- Установка: настройка `TELEGRAM_DECISIONS`.
- Изменение применяется после `notify-by-telegram`: оно пользуется его привязкой, шлюзом, задачей приёма обновлений и видами сообщений.
- Новых зависимостей нет.
