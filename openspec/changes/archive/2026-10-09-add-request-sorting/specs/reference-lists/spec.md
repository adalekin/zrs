# Spec Delta

## ADDED Requirements

### Requirement: Порядок приоритетов

Система SHALL хранить порядок значений справочника приоритетов и разрешать финансовому директору менять его, переставляя значение на другое место. Первым стоит самый важный приоритет. Новый приоритет встаёт последним. Справочник и список выбора в форме запроса показывают приоритеты в этом порядке.

Приоритеты называет сама организация, и по названию сервис не может знать, какой из них важнее. Порядок задаёт тот, кто ведёт справочник.

#### Scenario: Финансовый директор поднимает приоритет

- **WHEN** финансовый директор поднимает приоритет, который стоит вторым
- **THEN** этот приоритет стоит первым, а прежний первый вторым

#### Scenario: Новый приоритет

- **WHEN** финансовый директор добавляет приоритет в справочник из двух значений
- **THEN** новый приоритет стоит третьим

#### Scenario: Перестановка через несколько мест

- **WHEN** финансовый директор ставит третий приоритет на первое место
- **THEN** этот приоритет стоит первым, прежние первый и второй стоят вторым и третьим

#### Scenario: Места с таким номером нет

- **WHEN** финансовый директор ставит приоритет на четвёртое место в справочнике из трёх значений
- **THEN** система отклоняет действие, порядок не меняется

#### Scenario: Два приоритета добавлены одновременно

- **WHEN** два финансовых директора одновременно добавляют по приоритету
- **THEN** новые приоритеты занимают два разных места в конце справочника

#### Scenario: Порядок в форме запроса

- **WHEN** сотрудник открывает список приоритетов в форме запроса
- **THEN** приоритеты идут в порядке справочника

#### Scenario: Выключенный приоритет

- **WHEN** финансовый директор выключает приоритет и включает его снова
- **THEN** приоритет стоит на прежнем месте

### Requirement: Порядок приоритетов меняет только финансовый директор

Система SHALL NOT разрешать менять порядок приоритетов никому, кроме финансового директора.

От порядка приоритетов зависит, что согласующие видят первым, и вести его должен тот, кто ведёт справочник.

#### Scenario: Порядок меняет модератор

- **WHEN** модератор пытается поднять приоритет
- **THEN** система отказывает в действии, порядок не меняется

### Requirement: Порядок есть только у приоритетов

Система SHALL отклонять изменение порядка у видов операций и форм оплаты и показывать их по названию.

По этим справочникам запросы не сортируют, и порядок их значений ничего бы не значил.

#### Scenario: Финансовый директор поднимает вид операции

- **WHEN** финансовый директор пытается поднять вид операции
- **THEN** система отклоняет действие, справочник по-прежнему показан по названию
