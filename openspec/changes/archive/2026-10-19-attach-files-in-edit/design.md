# Design

## Context

- Одна форма `web/app/components/RequestForm.vue` служит и новому запросу, и правке; её показывает `RequestDialog.vue`. Блок документов в ней выводится только для нового запроса (`v-if="!request"`).
- Документы нового запроса выбираются в форме и загружаются по одному после создания запроса (`RequestForm.upload`); незагруженные файлы перечисляются в сообщении, и человек попадает на страницу запроса (`RequestDialog.finish`).
- Выбранные файлы переживают закрытие диалога, но не перезагрузку страницы: их держит `RequestDialog` (`files`), как черновик полей держит `sessionStorage` (архивный дизайн `2026-10-08-add-expense-requests`, решение о черновике относится и к правке).
- Страница запроса загружает файлы при выборе и удаляет сразу (`pages/requests/[id]/index.vue`: `upload`, `removeAttachment`, `FileDropzone` при `can_edit`), и выводит список файлов со ссылками на скачивание.
- Файл больше предела установки отсекает `FileDropzone.vue` до отправки и называет предел.
- API документов уже есть: `POST /v1/requests/{id}/attachments`, `DELETE /v1/requests/{id}/attachments/{attachment_id}`; сервер принимает их, пока запрос можно править.

## Goals / Non-Goals

**Goals:** документы меняются только в формах, правка документов применяется вместе с полями по «Сохранить»; страница просмотра только показывает документы.

**Non-Goals:** изменения сервера и API.

## Decisions

### 1. Изменения документов в форме это отложенные команды, применяемые по «Сохранить»

Паттерн: Unit of Work на стороне клиента. Форма копит изменения документов так же, как изменения полей: список выбранных файлов (`files`, уже есть) и список удаляемых приложенных файлов (`removed`). По «Сохранить» форма применяет их по порядку: правка полей (`PATCH`, только если поля изменились), удаление отмеченных файлов, загрузка новых. Закрытие формы без сохранения ничего не применяет, «Сбросить» очищает и поля, и оба списка. Отложенные изменения документов живут столько же, сколько черновик: переживают закрытие диалога, но не перезагрузку страницы; их держит `RequestDialog`, как выбранные файлы нового запроса.

Отвергнуто:
- загружать и удалять файлы сразу при выборе: отмена правки не отменяла бы изменения документов, и форма вела бы себя по-разному для полей и для файлов;
- отдельная кнопка сохранения документов внутри формы: два способа сохранить одну правку.

### 2. Загрузка и удаление документов живут только в форме

Страница запроса теряет `upload`, `removeAttachment` и `FileDropzone` и показывает документы списком ссылок на скачивание, без кнопки удаления. Загрузку и удаление выполняет `RequestForm` одним методом применения изменений для обоих режимов: у нового запроса список удаляемых пуст. Разбор ответа на превышение предела и на конфликт статуса переходит из страницы в форму вместе с загрузкой; второй копии цикла загрузки не остаётся.

Отвергнуто: composable загрузки для страницы и формы. У страницы загрузки больше нет, выделять общий код не для кого.

### 3. Блок документов формы показывает приложенные и выбранные файлы одним списком

`RequestForm` выводит блок документов в обоих режимах. В правке он сначала перечисляет приложенные файлы запроса (`request.attachments`), кроме отмеченных к удалению, с кнопкой удаления, затем выбранные новые файлы с кнопкой убрать, затем `FileDropzone`. Отдельный компонент списка не выделяется: разметка двух коротких списков проще компонента с пропсами.

## Risks / Trade-offs

- [Поля сохранились, а часть файлов не загрузилась] → форма закрывается, перечень незагруженных файлов показывается сообщением, человек оказывается на странице запроса и добавляет их снова через «Править»; так уже ведёт себя новый запрос.
- [Запрос сменил статус, пока форма была открыта] → сервер отклоняет и правку, и документы конфликтом статуса; форма показывает это сообщение, как сейчас для полей.
- [Пустой запрос без документов на странице просмотра] → страница пишет «Документов нет», как сейчас для того, кто не может править.
