# Proposal

## Why

Вид операции, приоритет и форма оплаты выглядят в запросах одинаковым текстом, а приоритета и формы оплаты в списке запросов нет. Тот, кто согласует и платит, не может с одного взгляда отличить срочный запрос от обычного и оплату наличными от перевода.

## What Changes

- Финансовый директор задаёт значению справочника цвет из палитры сервиса, меняет его и снимает.
- Список запросов показывает у каждого запроса вид операции, приоритет и форму оплаты.
- Значение с цветом выделено этим цветом в списке запросов и на странице запроса. Значение без цвета остаётся обычным текстом.
- Заголовком строки списка становится первая строка ситуации. Вид операции, который был заголовком, стоит теперь рядом с приоритетом и формой оплаты.
- Все страницы интерфейса становятся шире: 1280 px вместо 1152 px.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `reference-lists`: у значения справочника появляется цвет, который задаёт финансовый директор и который виден в списке запросов и на странице запроса.
- `expense-requests`: список запросов показывает вид операции, приоритет и форму оплаты каждого запроса.

## Impact

- Сервер: значение справочника хранит цвет, `PATCH /v1/reference-items/{id}` принимает его, значение справочника в ответах API несёт цвет. Схема базы получает одну миграцию.
- Веб-интерфейс: общая ширина страниц, страница «Справочники», список запросов и его карточки на узком экране, страница запроса, обе локали.
- README: снимки списка, карточек и страницы запроса.
- Новых зависимостей нет.
