# Proposal

## Why

Организации нужен один порядок согласования расходов: кто попросил деньги, кто утвердил, кто заплатил. Сервис ведёт запрос на расход средств от подачи до оплаты и ставится в любую организацию через настройки, без правки кода.

## What Changes

- Сотрудник подаёт запрос на расход средств и выбирает модератора.
- Модератор утверждает запрос сам, передаёт его финансовому директору, возвращает автору или отклоняет.
- Финансовый директор одобряет переданный запрос, возвращает его или отклоняет.
- Исполнитель выплаты отмечает оплату одобренного запроса и её дату.
- У каждого запроса есть журнал: смены статуса и комментарии с автором и временем.
- Запросы видны по ролям, у каждой роли есть отбор «ждут моего действия».
- Финансовый директор ведёт справочники видов операций, форм оплаты и приоритетов.
- Вход идёт через провайдера OpenID Connect организации, четыре роли приходят от него.
- Провайдер входа, соответствие ролей, валюты, язык интерфейса и хранилище вложений задаются настройками установки.

Не делаем:

- несколько организаций в одной установке;
- свои поля запроса и свою цепочку согласования для установки;
- уведомления;
- повторяющиеся запросы: период оплаты остаётся текстовой пометкой;
- историю правок полей запроса;
- установку в конкретное окружение: клиент у провайдера входа, DNS, база и манифесты кластера готовит тот, кто ставит сервис.

## Capabilities

### New Capabilities

- `expense-requests`: запрос на расход средств, его поля, согласование, оплата, видимость, списки и документы на оплату.
- `request-journal`: журнал запроса со сменами статуса и комментариями.
- `access-and-roles`: вход через внешнего провайдера, четыре роли и список людей сервиса.
- `reference-lists`: справочники видов операций, форм оплаты и приоритетов.
- `installation-settings`: настройки, которыми установка подключает сервис к своему окружению.

### Modified Capabilities

Нет.

## Impact

- Репозиторий пуст, всё создаётся заново: сервер с API в `server/`, веб-интерфейс в `web/`, миграции базы, два Docker-образа.
- Поставка: файл Docker Compose для запуска и Helm-чарт для Kubernetes в `deploy/`. Образы и чарт публикуются в GitHub Container Registry по git-тегу.
- Внешние системы установки: провайдер OpenID Connect, PostgreSQL, S3-совместимое хранилище.
- Зависимости только из публичных реестров пакетов.
- `docs/requirements.md` заменяется спеками этого изменения.
