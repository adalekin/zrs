## ADDED Requirements

### Requirement: Возврат исполнителем выплаты

Система SHALL давать исполнителю выплаты вернуть автору (статус «Ошибка») запрос в статусе «Одобрено», который он может оплатить: назначенный ему или без назначенного исполнителя. Действие есть и у периодического запроса, по которому уже есть оплаты; записанные оплаты при возврате сохраняются.

Исполнитель выплаты первым видит, что для оплаты не хватает счёта или другого документа, а приложить его может только автор в запросе, который можно править. Исправленный запрос снова проходит согласование, поэтому каждый документ, по которому платят, видят согласующие.

#### Scenario: Исполнитель возвращает запрос

- **WHEN** исполнитель выплаты, назначенный запросу, возвращает автору запрос в статусе «Одобрено» и пишет, что приложить
- **THEN** запрос переходит в статус «Ошибка», в журнале запись со статусом «Ошибка», исполнителем выплаты и его комментарием

#### Scenario: Автор прикладывает счёт к возвращённому запросу

- **WHEN** исполнитель выплаты вернул запрос, и автор добавляет к нему файл
- **THEN** файл появляется в запросе

#### Scenario: Запрос без исполнителя

- **WHEN** запросу в статусе «Одобрено» исполнитель не назначен, и его возвращает автору человек с ролью исполнителя выплаты
- **THEN** запрос переходит в статус «Ошибка»

#### Scenario: Возвращает другой исполнитель

- **WHEN** запросу назначен один исполнитель, а вернуть его автору пытается другой человек с ролью исполнителя выплаты
- **THEN** система отказывает в действии, статус не меняется

#### Scenario: Запрос не одобрен

- **WHEN** исполнитель выплаты возвращает автору запрос в статусе «Отмодерировано»
- **THEN** система отклоняет действие, статус не меняется

#### Scenario: Периодический запрос с оплатой

- **WHEN** исполнитель выплаты возвращает автору периодический запрос в статусе «Одобрено», по которому уже есть две оплаты
- **THEN** запрос переходит в статус «Ошибка», обе оплаты остаются записанными

#### Scenario: Исполнитель выплаты на возвращённом запросе

- **WHEN** исполнитель выплаты возвращает автору запрос, которому он назначен, и автор отправляет запрос заново без правки исполнителя
- **THEN** исполнителем выплаты у запроса остаётся тот же человек

### Requirement: Периодичность и валюта запроса с оплатой

Система SHALL NOT давать автору менять периодичность и валюту запроса, по которому уже есть оплата. Остальные поля и файлы такого запроса автор правит по общим правилам.

Записанные оплаты хранят сумму в валюте запроса и отмечены по периодам его периодичности. Другая валюта исказила бы прошлые суммы, а запрос без периодичности закрылся бы следующей оплатой.

#### Scenario: Автор убирает периодичность у запроса с оплатой

- **WHEN** исполнитель выплаты вернул периодический запрос с оплатой, и автор убирает у него периодичность
- **THEN** система отклоняет правку, в ответе названо поле периодичности, запрос остаётся прежним

#### Scenario: Автор меняет период у запроса с оплатой

- **WHEN** автор меняет ежемесячную периодичность возвращённого запроса с оплатой на ежеквартальную
- **THEN** система отклоняет правку, в ответе названо поле периодичности

#### Scenario: Автор меняет валюту у запроса с оплатой

- **WHEN** автор меняет валюту возвращённого запроса с оплатой
- **THEN** система отклоняет правку, в ответе названо поле валюты

#### Scenario: Автор меняет сумму у запроса с оплатой

- **WHEN** автор меняет сумму возвращённого периодического запроса с оплатой
- **THEN** новая сумма сохраняется, записанные оплаты не меняются

#### Scenario: Запрос без оплат

- **WHEN** автор меняет валюту и периодичность запроса в статусе «Ошибка», по которому оплат нет
- **THEN** новые значения сохраняются

## MODIFIED Requirements

### Requirement: Отмена автором

Система SHALL разрешать автору отменить свой запрос в статусах «Новая», «Ошибка», «Отмодерировано» и «Одобрено», пока по запросу нет ни одной оплаты. Отменённый запрос получает статус «Отказ».

Автор может передумать, пока деньги не выплачены.

#### Scenario: Автор отменяет одобренный запрос

- **WHEN** автор отменяет свой запрос в статусе «Одобрено»
- **THEN** запрос переходит в статус «Отказ»

#### Scenario: Автор отменяет оплаченный запрос

- **WHEN** автор отменяет свой запрос в статусе «Оплачено»
- **THEN** система отклоняет действие, статус не меняется

#### Scenario: Автор отменяет периодический запрос с оплатой

- **WHEN** автор отменяет свой периодический запрос в статусе «Одобрено», по которому уже есть оплата
- **THEN** система отклоняет действие, статус не меняется

#### Scenario: Автор отменяет возвращённый периодический запрос с оплатой

- **WHEN** исполнитель выплаты вернул автору периодический запрос, по которому уже есть оплата, и автор отменяет его в статусе «Ошибка»
- **THEN** система отклоняет действие, статус не меняется

#### Scenario: Автор отменяет повторно поданный периодический запрос с оплатой

- **WHEN** автор отправил заново возвращённый периодический запрос, по которому уже есть оплата, и отменяет его, пока тот ждёт решения согласующего
- **THEN** система отклоняет действие, статус не меняется
