# Proposal

## Why

Список показывает запросы подряд: чтобы понять, сколько запросов и на какую сумму стоит на каждом шаге согласования, их приходится пересчитывать глазами. Сервис не отправляет уведомлений, и картину «что на каком этапе» человек получает только с экрана.

## What Changes

- Запросы в работе открываются доской: четыре колонки по статусам в порядке пути запроса.
- В заголовке колонки число запросов и сумма по каждой валюте.
- Карточка запроса показывает первую строку ситуации, сумму, вид операции, приоритет, форму оплаты, автора, номер и дедлайн.
- Карточки, которые ждут действия смотрящего, отмечены.
- Завершённые запросы стоят под доской счётчиками и ведут в список.
- Список и доска переключаются на странице запросов.
- На узком экране доска показывает одну колонку за раз.

## Capabilities

### New Capabilities

- `request-board`: доска запросов по статусам: колонки, итоги колонок, карточки, завершённые запросы, переключение со списком.

### Modified Capabilities

- `reference-lists`: цвет значения справочника виден и на карточке доски.

## Impact

- Сервер: новый маршрут чтения итогов по статусам, `GET /v1/request-totals`. Схема базы не меняется.
- Веб-интерфейс: страница запросов, новые компоненты доски и её карточки, общие функции строки запроса, обе локали.
- README: снимок доски.
- Новых зависимостей нет.
