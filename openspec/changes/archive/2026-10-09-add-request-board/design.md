# Design

## Context

Мотивация и объём описаны в `proposal.md`, поведение в `specs/`. Здесь только то, на чём стоят решения.

- Страница запросов держит вкладку, отбор по статусу и номер страницы в адресе; вкладки «Ждут меня» и «Все» задают отбор `awaiting_me` (`web/app/pages/index.vue`; решение 21 в `openspec/changes/archive/2026-10-08-add-expense-requests/design.md`).
- Пометку «ждёт вас» строка списка получает по множеству идентификаторов из ответа API с отбором `awaiting_me`: правило очереди интерфейс не повторяет (там же, `waitingIds`).
- `GET /v1/requests` отдаёт страницу запросов с отбором `status` и `awaiting_me`, размер страницы не больше 100 (`server/internal/controller/http/v1/requests.py`).
- Видимость и очередь заданы двумя спецификациями, `VisibleTo` и `AwaitingActionOf`; ими пользуется каждое чтение запросов (`server/internal/service/expense_request.py`; решение 7 архивного `design.md`).
- Сумма хранится числом `NUMERIC(20, 4)` и передаётся в API строкой, у запроса своя валюта (решение 11 там же).
- Маршруты API плоские: `/v1/requests`, `/v1/reference-items`, `/v1/users`. Идентификатор запроса в `/v1/requests/{request_id}` целый (`server/internal/controller/http/router.py`, `requests.py`).
- Сторона, у которой запрос, выводится из статуса таблицей `HOLDERS` в `web/app/utils/holder.ts`: `returned` у автора, `new` у модератора, `escalated` у финансового директора, `approved` у исполнителя выплаты. Завершённые статусы стороны не имеют.
- Страница запроса рисует путь по сторонам в порядке «автор, модератор, финансовый директор, оплата»; порядок записан в ней массивом (`web/app/pages/requests/[id]/index.vue`, `steps`).
- Первую строку ситуации и просрочку дедлайна считают функции `gist` и `overdue` внутри `web/app/pages/index.vue`.
- На экране уже 640 px список показывается карточками (`web/app/pages/index.vue`).
- Данные API страница получает через `useLoad`: загрузка при открытии и по вызову `reload`, без кеша между посещениями (`web/app/composables/useLoad.ts`).
- Значение справочника рисует компонент `ReferenceValue`, статус рисует `StatusBadge` (`web/app/components`).

## Goals / Non-Goals

**Goals:**

- Правила видимости и очереди на доске те же, что в списке, и записаны в одном месте сервера.
- Итог колонки верен при любом числе запросов.
- Страница запросов остаётся владельцем вкладок и вида, доска живёт отдельным компонентом.

**Non-Goals:**

- Перенос карточек между колонками и любые действия над запросом с доски.
- Порядок карточек внутри колонки, отличный от порядка списка, и его выбор.
- Обновление доски без перезагрузки, пока страница открыта.
- Настройка состава и порядка колонок.

## Decisions

### 1. Доска это второй вид страницы запросов

Паттерн: состояние экрана в адресе, как у вкладки и отбора по статусу. Адрес получает параметр `layout=board`; без него страница показывает список. Вкладки «Ждут меня» и «Все», кнопка нового запроса и диалог подачи общие для обоих видов. Отбор по статусу показан только у списка: на доске статусы стали колонками.

Переключатель вида стоит в строке заголовка страницы, справа, перед кнопкой нового запроса: две кнопки с подписями «Список» и «Доска».

На экране уже 640 px переключателя вида нет, страница показывает один вид (решение 7).

Отклонено:

- отдельная страница доски: вкладки, счётчик очереди и подача запроса повторились бы на двух страницах;
- выбранный вид в хранилище браузера: ссылка на страницу открывала бы у другого человека другой вид.

### 2. Колонки выводятся из таблицы сторон

Колонками служат статусы, у которых есть сторона, в порядке пути запроса: `returned`, `new`, `escalated`, `approved`. Порядок сторон «автор, модератор, финансовый директор, исполнитель выплаты» становится общей константой в `web/app/utils/holder.ts`; из неё берут порядок и доска, и путь на странице запроса. Под названием статуса заголовок колонки называет сторону теми же словами, что список.

Отклонено:

- отдельный список статусов доски: порядок шагов оказался бы записан дважды, на странице запроса и на доске;
- колонка «Ошибка» последней: запрос в этом статусе вернулся к автору, то есть в начало пути.

### 3. Карточки колонки отдаёт существующий маршрут списка

Доска запрашивает `GET /v1/requests` по разу на колонку: `status` колонки, `size=100`, тот же `awaiting_me`, что у вкладки. Карточки идут в порядке списка. Четыре вызова идут одновременно.

Когда в статусе больше ста запросов, колонка показывает сто карточек и строку «ещё N в списке» со ссылкой на список с отбором по статусу. Число N считается из итога колонки.

Отклонено:

- маршрут `GET /v1/board`, который отдаёт всю доску: контракт API узнал бы о виде одного экрана, а отбор и видимость повторились бы во втором месте;
- догружать колонку страницами до конца: на установке с тысячами запросов доска открывала бы их все.

### 4. Итоги считает сервер

Паттерн: Specification и запрос-агрегат. Новый маршрут `GET /v1/request-totals` принимает `awaiting_me` и отдаёт по записи на каждый из шести статусов: статус, число запросов и суммы по валютам. Статус без запросов приходит с нулём и пустым списком сумм. Сумма передаётся строкой, как сумма запроса.

```
[{ "status": "new", "count": 4, "amounts": [{ "currency": "RUB", "amount": "176400.0000" }, { "currency": "USD", "amount": "199.0000" }] }, ...]
```

Запрос группирует по статусу и валюте и фильтрует теми же `VisibleTo` и `AwaitingActionOf`, что список. Метод `totals` живёт в `ExpenseRequestService` рядом с `page`. Маршрут описан своим роутером `request_totals.py` и своими DTO.

Из этого ответа доска берёт число и суммы четырёх колонок и число завершённых запросов под доской.

Отклонено:

- суммы на клиенте из загруженных карточек: при ста с лишним запросах сумма была бы меньше настоящей;
- число из поля `total` списка, а суммы отдельно: у одного числа появилось бы два источника;
- адрес `/v1/requests/totals`: рядом стоит `/v1/requests/{request_id}` с целым идентификатором, и маршрут зависел бы от порядка объявления.

### 5. «Ждёт вас» приходит от страницы

Страница уже держит множество идентификаторов запросов своей очереди. Она передаёт его доске, и карточка из этого множества получает рамку основного цвета и подпись «ждёт вас», как панель решения на странице запроса. На вкладке «Ждут меня» отмечены все карточки.

Отклонено: считать очередь на клиенте по ролям человека. Это уже отклонено решением 21 архивного `design.md`: правило очереди есть на сервере.

### 6. Компоненты

Паттерн: контейнер и презентационный компонент.

- `RequestBoard.vue` владеет загрузкой четырёх колонок и итогов. Принимает отбор `awaiting_me` и множество «ждут меня». Наружу отдаёт только перезагрузку.
- `RequestBoardCard.vue` рисует карточку по запросу и признаку «ждёт вас». Состояния нет.
- `pages/index.vue` остаётся владельцем вкладок, вида, счётчика очереди и диалога подачи. После подачи запроса она перезагружает тот вид, который открыт.

Карточка: сверху вид операции слева и приоритет справа, ниже первая строка ситуации в две строки, ниже сумма и форма оплаты, внизу автор с номером и дедлайн. У каждого справочника своё место, поэтому значения не переносятся и карточки одной ширины читаются одинаково.

Функции `gist` и `overdue` переезжают из страницы в `web/app/utils/request.ts`: ими пользуются и список, и карточка доски.

Не трогаются: таблица списка и его карточки на узком экране остаются в `pages/index.vue`.

Отклонено:

- доска внутри `pages/index.vue`: страница выросла бы вдвое и держала бы загрузку двух видов сразу;
- общая карточка для списка на узком экране и для доски: у них разный состав, карточка списка несёт статус, карточка доски нет.

### 7. Узкий экран

На экране уже 640 px страница запросов показывает один вид: список карточками. Параметр `layout` в адресе на таком экране не действует, доска не загружается. Ширину экрана страница узнаёт из композабла `useNarrow` (медиазапрос `max-width: 639px`, значение следит за изменением ширины).

Заголовок страницы занимает три ряда, каждый стоит на краях карточек:

1. название страницы, кнопка порядка и кнопка нового запроса;
2. вкладки «Ждут меня» и «Все» одним переключателем на всю ширину;
3. на вкладке «Все» ряд статусов.

Ряд статусов рисует компонент `RequestStatusStrip.vue`: статусы в работе в порядке пути запроса, за ними завершённые, у каждого число из `GET /v1/request-totals`. Компонент сам загружает итоги и сообщает выбор; выбранный статус страница хранит в том же параметре `status`, что отбор списка. Ряд прокручивается по горизонтали и выходит за правый край экрана: обрезанный краем статус показывает, что ряд длиннее. Выбранный статус снимается повторным нажатием и несёт крестик.

Контролы заголовка одной высоты и одного скругления. Скруглённые до круга плашки остаются за статусами внутри карточек: то, что нажимается, не выглядит как то, что не нажимается.

Верхняя панель приложения на таком экране занимает одну строку: имя и роли человека скрыты, выход показан значком.

Отклонено:

- доска с одной колонкой и переключателем статусов: тот же список с отбором по статусу под вторым набором управления;
- четыре колонки с горизонтальной прокруткой: страница прокручивалась бы в двух направлениях, а соседние колонки были бы видны наполовину;
- отбор по статусу выпадающим списком: числа по статусам оказались бы скрыты за нажатием;
- суммы по статусам на телефоне: строка под рядом статусов отодвигала бы первую карточку, а суммы нужны тому, кто планирует выплаты, на большом экране.

### 8. Завершённые запросы

Под доской строка «Завершённые»: статусы «Оплачено» и «Отказ» теми же плашками, что в списке, с числом из итогов. Каждый ведёт на список с вкладкой «Все» и отбором по статусу.

## Risks / Trade-offs

- [Доска делает пять вызовов API при открытии] → вызовы идут одновременно и читают одну таблицу по индексу статуса.
- [Карточки и итоги приходят разными вызовами, между ними чей-то запрос сменил статус] → число в заголовке на миг расходится с числом карточек; следующее открытие доски показывает согласованную картину.
- [В статусе больше ста запросов] → колонка показывает сто карточек и ссылку на список; итог в заголовке считается по всем.
- [Доска не обновляется сама] → как и список: страница показывает то, что сервер отдал при открытии.
- [Человек ждёт, что карточку можно перетащить] → курсор над карточкой обычный для ссылки, карточка открывает запрос.
