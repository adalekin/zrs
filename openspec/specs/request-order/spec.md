# request-order Specification

## Purpose
Порядок запросов задаёт, что человек видит первым в списке и в колонках доски: самое важное, самое срочное или самое новое.

## Requirements

### Requirement: Сортировка списка

Система SHALL давать человеку упорядочить список запросов по приоритету, по дедлайну или по дате подачи, в любую сторону. Порядок действует на весь список, а не на открытую страницу.

Согласующий решает сначала важное и срочное, а список от новых к старым прячет такие запросы среди остальных.

#### Scenario: По приоритету

- **WHEN** человек сортирует список по приоритету
- **THEN** сверху стоят запросы с приоритетом, который финансовый директор поставил первым в справочнике

#### Scenario: По дедлайну

- **WHEN** человек сортирует список по дедлайну
- **THEN** сверху стоит запрос с самым близким дедлайном

#### Scenario: Обратная сторона

- **WHEN** человек второй раз выбирает сортировку по дедлайну
- **THEN** порядок запросов с дедлайном становится обратным: сверху самый дальний дедлайн

#### Scenario: Вторая страница

- **WHEN** человек сортирует список по приоритету и открывает вторую страницу
- **THEN** вторая страница продолжает порядок первой

### Requirement: Запросы с равным значением

Система SHALL ставить при сортировке по приоритету запросы одного приоритета по дедлайну, ближайший первым, а при сортировке по дедлайну запросы с одним дедлайном по приоритету. Запросы, равные и по приоритету, и по дедлайну, идут по дате подачи, раньше поданный первым.

Среди срочных первым нужен тот, у которого раньше дедлайн, а среди равных тот, что ждёт дольше.

#### Scenario: Два срочных запроса

- **WHEN** человек сортирует по приоритету список с двумя запросами высшего приоритета, с дедлайнами 9 и 15 октября
- **THEN** запрос с дедлайном 9 октября стоит выше

#### Scenario: Равные запросы

- **WHEN** два запроса одного приоритета поданы без дедлайна в разные дни
- **THEN** при сортировке по приоритету выше стоит поданный раньше

### Requirement: Запросы без дедлайна

Система SHALL ставить запросы без дедлайна ниже запросов с дедлайном там, где порядок зависит от дедлайна, в любую сторону сортировки.

Запрос без дедлайна не срочнее запроса с дедлайном, каким бы далёким тот ни был.

#### Scenario: Сортировка по дедлайну

- **WHEN** человек сортирует по дедлайну список, где у части запросов дедлайна нет
- **THEN** запросы без дедлайна стоят после всех запросов с дедлайном

#### Scenario: Обратная сторона

- **WHEN** человек переворачивает сортировку по дедлайну
- **THEN** запросы без дедлайна по-прежнему стоят после всех запросов с дедлайном

### Requirement: Завершённые запросы при сортировке

Система SHALL ставить при сортировке по приоритету и по дедлайну запросы в статусах «Оплачено» и «Отказ» ниже запросов в работе.

Приоритет и дедлайн отвечают на вопрос «что решать первым», а завершённые запросы решать уже не нужно.

#### Scenario: Оплаченный запрос с прошедшим дедлайном

- **WHEN** человек сортирует по дедлайну список, где у оплаченного запроса дедлайн раньше, чем у всех запросов в работе
- **THEN** оплаченный запрос стоит ниже всех запросов в работе

#### Scenario: Сортировка по дате подачи

- **WHEN** человек сортирует список по дате подачи
- **THEN** завершённые запросы стоят среди остальных по своей дате подачи

### Requirement: Порядок карточек на доске

Система SHALL упорядочивать карточки всех колонок доски одним выбранным порядком: по приоритету, по дедлайну или от новых к старым. Пока человек не выбрал порядок, карточки идут по приоритету.

Колонка это очередь одного шага: сверху должно стоять то, что решать первым.

#### Scenario: Доска без выбранного порядка

- **WHEN** человек открывает доску, не выбирая порядок
- **THEN** в каждой колонке сверху стоят карточки высшего приоритета, среди них первой карточка с ближайшим дедлайном

#### Scenario: Порядок по дедлайну

- **WHEN** человек выбирает на доске порядок по дедлайну
- **THEN** во всех четырёх колонках сверху стоят карточки с ближайшим дедлайном

### Requirement: Порядок в адресе страницы

Система SHALL хранить выбранный порядок в адресе страницы запросов.

Ссылка на страницу и её перезагрузка должны показывать запросы в том порядке, в каком их видел человек.

#### Scenario: Перезагрузка страницы

- **WHEN** человек сортирует список по дедлайну и перезагружает страницу
- **THEN** список снова отсортирован по дедлайну
